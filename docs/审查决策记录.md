## D8 · 主按钮与品牌主色统一（D5 遗留结案，2026-09）
- **背景**：D5/D6 为避免小号白字跌破 AA，把主行动切成深档 `#B23A63→#9E3054`。结果主按钮呈**酒红/深玫**，与品牌主色 `#F77FA3` 观感脱节——设计负责人反馈「按钮没有和主题色统一起来」。
- **约束（算术，非口味）**：`#F77FA3` 上白字仅 **2.46:1**，`--mmh-grad-primary` 深端 `#E85D8F` 上白字 3.28 / 深字 3.48 —— **亮渐变两端都无法承载小号文字**。因此「按钮=主题色」只有两条数学成立的路：亮底+深字，或同族加深+白字。
- **裁决（选同族加深+白字，保留白字惯例）**：`--mmh-grad-action-hc` 定为 **`#C44C74→#B23A63`**（**取值已由 D9 上移为 `#FFC4D6→#F77FA3` + 深字**）。原取值方法：在品牌主色 `#F77FA3` → 深玫 `#B23A63` 的 RGB 连线上，取**仍能通过白字 AA 的最亮值** `#C44C74`（白字 4.53:1）。
- **对比 D7 先例**：D7 曾因 `#C94A77` 白字 4.44:1 不足而退回 `#B23A63`。本档亮端 4.53 同样贴线，依据是**渐变上文字居中，实际承载面约为渐变中段 `#BB436B`（白字 ≈5.09:1）**，亮端仅为角落极值；如需更保守余量，把亮端下调至 `#C0486F` 档即可（单点改动）。

## D9 · 主行动改为品牌粉 + 深字（D8 取值上移，2026-09）
- **背景**：D8 把主行动定为品牌同族加深档 `#C44C74→#B23A63` + 白字（4.53–5.71 过 AA），但设计负责人要求按钮**直接用品牌主色 `#F77FA3`**。
- **约束（算术）**：白字在 `#F77FA3` 上仅 **2.46:1**，连大字号 3:1 都不到 → 「按钮 = 主题色 + 白字」这条路**不存在**。要让按钮用上 `#F77FA3`，只能把文字**由白转深**。
- **裁决**：`--mmh-grad-action-hc` = `linear-gradient(135deg,#FFC4D6 0%,#F77FA3 100%)`（= Rose-300→Rose-500，**品牌粉上半段**）+ 文字 `#343A46`。取值理由：不得含 `#E85D8F` 深端——该色上深字 3.48、白字 3.28，**两个方向都不达标**，故只取品牌粉上半段。
- **实测**（CSS 规范插值 `t=(x+y)/(W+H)`，按 03·3.2.2 尺寸表算**文字框内最坏点**）：XS 5.16 / S 5.14 / M 5.10 / M 长文案 4.89 / L 5.00 —— 全尺寸 ≥4.5；渐变亮端 7.67、暗端角落 4.63。**余量比 D8 的 4.53–5.71 更大**。
- **落地**：token（`theme.css` 真源 + `gm.css` + 9 处页面声明与 fallback）；以该 token 为底的控件文字由白转深（71 处自动替换）；**Arco primary 默认白字必须显式覆盖** —— `theme.css` `.gm-btn.arco-btn-primary`、`gm.css` 同名规则、`theme.css` `.gm-btn-hc` 三处补 `color:#343A46!important`；`fuyouaicansai/goodmom-redesign.html` 主变量 `--g` 及其 **7 处白字控件**、手册顶栏 `.top a`（`gen-manual.py` + `site/manual.html` 同步）。

- **二分口径（取代 D5/D6 的"白字必须深底"单一口径）**：① **深实底 + 白字** → `--mmh-solid-*`（4.7–7.0:1）；② **品牌粉底 + 深字** → `--mmh-grad-action-hc` + `#343A46`（4.89–7.67:1）。**禁止「品牌亮粉底 + 白字」**。

### P0 · 暗色模式在合并站点**完全失效**（本轮最重要发现）

- **现象**：`preview-patterns` 的「切换本页整体暗色（data-theme）」按钮点下去**按钮文案会变、`data-theme` 也确实挂上了，但页面纹丝不动**（`--t3`、`.glass` 底纹、模块底色全是浅色档）。首页因此长期挂着一个"假开关"。
- **根因（在生成器里，不在产物里）**：`build-site.py` 的 CSS 作用域改写把原页面的
  `[data-theme="dark"] .glass{…}`（原语义：`<html data-theme>` 是**祖先**）改写成
  `.gm-mod--x [data-theme="dark"] .glass`（**后代**）—— 而 `rewrite_page_dark_css` / `rewrite_page_dark_js`
  已把该属性改挂在**模块根自身**上，模块内部根本没有带该属性的后代，于是**全部暗色规则永不命中**。
- **裁决与落地**：在 `scope_selector` 增加一条——以 `[data-theme=…]` / `:where([data-theme=…])` 开头
  的选择器必须写成**复合**（`.gm-mod--x[data-theme="dark"] …`），而不是后代。复合形式特异性更高，

### 工具口径校正（避免把合规实现报成违规）

渲染级检查必须自己先"站得住"，否则会诱导错误的修复方向：

- **禁用态豁免**：WCAG 1.4.3 明文豁免失效/禁用控件；禁用态用低对比表达"不可用"是正确做法，不该被算成违规。
- **规范正文 ≠ 界面**：`site-spec` / `site-manual` 是规范正文阅读器，正文里的 🟢 图例与版本沿革是**文档内容**，不计入「界面禁 emoji」与「同页版本号不一致」。
- **`:after` 热区是合规实现**：10 章明确允许用 `::after` 扩热区，伪元素没有 `getBoundingClientRect`，只量元素盒会把它误判成违规。
- **`02 · 2.4` 只管「组件与容器」**：任一短边 <32px 的微元素与 `display:inline` 的行内盒子（`code` 芯片、进度条、色点）不在圆角档位管辖内 —— 把 18px 套到 12px 高的 chip 上反而是错的。
- **暗色能力缺口 ≠ 违规**：`dark-missing` 记为 P3。token 层是否支持暗色由 `audit.py` 的 `dark` 检查守；各展示模块是否自带暗色皮肤是**能力缺口**，登记不阻塞。

## D16 · 按钮视觉统一（主按钮"描边错行发脏" + 白底按钮"描边廉价"，2026-09）
